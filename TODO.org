* Design principle: open-ended client (octocrab-style escape hatch)
:PROPERTIES:
:CATEGORY: design
:END:

The Salesforce REST surface is large and growing. We will *not* race
Salesforce to wrap every endpoint. Instead, the client must always
expose a low-level escape hatch so a user can call any
=/services/data/...= URL we haven't typed yet — without giving up auth,
the configured instance URL, retry policy, or =tracing= spans.

This is the same contract [[https://github.com/XAMPPRocky/octocrab][Octocrab]] offers for GitHub: typed
builders for the common surface, plus =get= / =post= / =put= / =patch=
/ =delete= methods that take a path + serializable body and return
either typed JSON or =serde_json::Value=.

** Required surface
- =Client::get<R: DeserializeOwned>(path, query) -> Result<R>=
- =Client::post<B: Serialize, R: DeserializeOwned>(path, body) -> Result<R>=
- =Client::put / patch / delete= — symmetrical
- =Client::execute(reqwest::Request) -> Result<reqwest::Response>= —
  full bypass for unusual cases (multipart upload, custom headers,
  binary download, SSE).
- =Client::request_builder(method, path) -> reqwest::RequestBuilder=
  — pre-authenticated, pre-baseurl'd, but not yet sent. Lets the
  caller compose anything reqwest can express.

** Path semantics
- Relative path (=sobjects/Account/001...=) → resolved against
  =instance_url + /services/data/{version}/=.
- Path with leading =/= (=/services/apexrest/foo=) → resolved against
  =instance_url= directly. Mirrors how Salesforce's own
  =nextRecordsUrl= comes back as an absolute path under the instance.
- Fully-qualified =https://...= URL → used as-is. Useful for
  =nextPageUrl= / Bulk 2.0 job result locators.

** What still flows through automatically
- =Authorization: Bearer ...= header from the configured =AuthFlow=
  (refresh-on-401 still applies).
- Configured =api_version= for relative paths.
- Retry / backoff (once that lands).
- =tracing= span around the request (once that lands).

** Why this matters now (not later)
- Unblocks every "we don't have a builder for X yet" complaint with a
  one-liner answer.
- Forces us to design the =Client= around composable layers
  (auth → base URL → request) instead of letting typed builders
  accidentally short-circuit those layers.
- Lets us *delete* speculative typed builders if usage data shows the
  raw escape hatch is fine; we can't easily un-ship a typed wrapper.

** Non-goals
- We do *not* try to make the escape hatch ergonomic enough to replace
  builders for high-traffic resources. CRUD, query, search etc. should
  feel nicer than the raw call.
- We do *not* expose internal modules (=token_endpoint=, etc.) just
  because the escape hatch exists. The escape hatch is for *Salesforce
  REST*, not for our auth internals.

* Cross-cutting infrastructure [4/10]
** DONE Open-ended client escape hatch
- Public =get= / =get_with_query= / =post= / =put= / =patch= / =delete= on =Cloudburst=, plus =request_builder(method, path)= (auth-injected) and =execute(reqwest::Request)= (hands-off) for full bypass.
- Three-mode path resolution in =Cloudburst::resolve_url=: relative → versioned, leading-=/= → instance-rooted, =http(s)://= → passthrough. Locks in the [[*Design principle: open-ended client (octocrab-style escape hatch)][design-principle contract]].
- Existing handlers (=versions=, =query::query_more=) migrated to use the public =get=; legacy =get_unversioned= / =versioned_url= / =instance_url= / =send_versioned= helpers removed.
- *Note for the next builder:* with the escape hatch in place, every new typed handler should layer over the public verbs (or =versioned_segments= + =send_at= when path encoding is needed) — not introduce parallel transport code.
** DONE Pagination stream (=pagination::Records<R>= implementing =futures::Stream=)
- New top-level =pagination= module. =Records<R>= is a runtime-agnostic =futures::Stream<Item = CloudburstResult<R>>= that walks =nextRecordsUrl= locators transparently.
- Public API: =Cloudburst::query_stream= / =query_stream_as<R>= / =query_all_stream= / =query_all_stream_as<R>=, plus =ToolingHandler::query_stream= / =query_stream_as<R>=.
- Lazy: each page fetch fires only when the previous page's buffer is drained. Drop the stream → no further requests. Verified by wiremock =.expect(0)= on a non-required follow-up locator.
- Errors mid-stream surface once and terminate the stream (no retry — that's the retry-policy infra's job, separate item).
- Runtime-agnostic by construction: only depends on =futures::Stream= and =BoxFuture=, which are runtime-neutral. Consumers can drive with smol/async-std/tokio — no =#[tokio::main]= required at the consumer level. ** TODO Property tests for URL / encoding / parser invariants [#B]
- *What:* Add =proptest= as a dev-dependency and write property tests for the cheap-but-load-bearing helpers:
  - =Cloudburst::versioned_segments= — for any segment string, the resulting URL parses back to the same segments and never contains =//= outside the scheme.
